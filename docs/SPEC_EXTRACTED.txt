QuantScore V1
机器可执行评分规则规范
冻结版 v1.1 · 供 Codex / Python 实现





文档目的
将手写炒股笔记中的交易逻辑转成可追溯、可测试、不可由代码生成模型自由发挥的机器规则。
基础来源
用户 21 页《炒股笔记》及用户对 T板、N板、一字T 等概念的补充说明。
规则边界
笔记未给出数字阈值的地方，本文用“V1 工程假设”明确标记；这些阈值需后续通过回测与用户反馈调整。
用途声明
用于求职 Demo、个人研究和规则实验，不构成投资建议，不预测未来收益。

1. 文档使用原则
本规范是 QuantScore V1 的唯一评分真源（Single Source of Truth）。Codex/程序不得自行新增指标、阈值、权重、形态定义或买卖结论。
每条规则必须可追溯到 Rule ID、原始数据、计算过程、最终判定和解释文本。
任何无法由数据可靠判断的规则必须返回 UNKNOWN；UNKNOWN 不等于 FAIL，不得用 0 分偷偷代替“无法判断”。
“笔记原意”和“V1 工程形式化”必须分开。工程阈值是为了可执行而设置，不代表已经通过历史统计证明最优。
系统输出的是“策略匹配度”，不是“上涨概率”“买入建议”或“收益承诺”。
所有时间序列计算禁止使用未来数据；回测时任何规则只能读取评价日及其之前的数据。
v1.1 用户补充冻结：本次补充空中加油、上升安全带、M60起飞平台、周线成交量反转、阻尼运动、板块龙头、底部小连阳、N板、T板、鲤鱼跃龙门+假摔及“该涨不涨”的原始定义。若 v1.0 中对应规则与本次定义冲突，以 v1.1 为准；工程阈值仍必须配置化并标记为 V1 工程参数。

FinalQuantScore = max(0, PositiveScore - RiskPenalty)
85–100：高度符合当前交易策略；70–84：较符合；55–69：信号混合；40–54：匹配度较低；0–39：明显不符合。
Risk Level 与 FinalQuantScore 分开显示。高分不能掩盖 HIGH RISK。

3.2 统一派生变量
M5(t) = mean(close_adj[t-4:t])
M20(t) = mean(close_adj[t-19:t])
M30(t) = mean(close_adj[t-29:t])
M60(t) = mean(close_adj[t-59:t])
VMA20(t) = mean(volume[t-19:t])
volume_ratio_20(t) = volume[t] / VMA20(t-1)    # 分母默认不含当日，避免自身稀释
return_Nd(t) = close_adj[t] / close_adj[t-N] - 1
position_120(t) = (close_adj[t]-min(low_adj[t-119:t])) / (max(high_adj[t-119:t])-min(low_adj[t-119:t]))
M60_slope_10(t) = M60(t) / M60(t-10) - 1
ATR10_pct(t) = ATR10(t) / close_adj[t]

8. UNKNOWN、Coverage 与自动筛股
8.1 Coverage（数据覆盖率）
PositiveCoverage = 已成功判定(PASS/PARTIAL/FAIL)的正向规则最大分值 / 100
RiskCoverage = 已成功判定的风险规则数量 / 当前应适用风险规则数量
Coverage
显示策略
>=90%
FULL：可显示完整QuantScore。
70%~90%
PARTIAL：显示分数，但明显标注“部分规则缺数据”。
<70%
INSUFFICIENT：不输出强等级，只显示已判定规则明细。

8.2 自动选股 AutoScreenScore
自动扫描时只允许使用 AUTO / AUTO_PROXY / AUTO_IF_DATA（数据实际存在时）规则；MANUAL/UNKNOWN 不得默认当作满足。
先计算 SectorHeatScore，默认只扫描 Heat>=70 的板块；按热度取 Top 5，可配置。
对每个板块成分股要求至少120个交易日日线；关键字段缺失导致 AutoCoverage<80% 时不得进入排名。
AutoPositiveMax 为本次实际可自动判定的正向最大分值；AutoPositiveNormalized = 100×AutoPositiveRaw/AutoPositiveMax。
AutoScreenScore = max(0, AutoPositiveNormalized - AutoRiskPenalty)。
若 AutoRiskLevel=HIGH，默认进入“高风险候选”区，不进入主排名前列；除非用户显式取消该过滤器。
排名主键：AutoScreenScore降序；同分时依次比较 RiskPenalty升序、SectorHeatScore降序、Coverage降序。
页面名称必须是“策略匹配候选/Top Strategy Matches”，不得写“推荐买入”。

不得新增本规范不存在的技术指标、形态、阈值或分数。需要新增时必须先修改规范版本。
不得把“筹码峰”“主力建仓”“龙头带动”等无法直接证明的概念擅自从K线推断为事实；只能使用本文定义的代理指标，并在字段名中保留 proxy。
涨停价必须来自证券元数据/行情源或独立的 market_rule 模块计算；不得统一写死为10%。
缺少分钟数据时 R6 必须 UNKNOWN；缺少筹码分布时 E4/E5/R10 必须 UNKNOWN。
UNKNOWN 不允许自动改成0后继续宣称Coverage=100%。
形态检测函数必须返回中间条件和触发日期，禁止只返回一个True/False。
所有回测和排名必须避免未来数据泄漏，尤其LOCAL_PEAK/LOCAL_TROUGH在实时模式下需要等待右侧2个交易日确认；实时模式可输出“候选峰/谷”，不得伪装已确认。
同一事件的互斥/去重必须按照第7章执行。
自动选股只能按AutoScreenScore排序；人工信号未填写时不能默认成立。
UI不得显示“强烈买入/必涨/预测收益率”等超出本规范含义的结论。
